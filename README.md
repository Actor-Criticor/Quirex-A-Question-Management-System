# Quirex

**本地优先的高中数学题库工具 —— 结构化录入 · 分面检索 · 一键导出可编译的 LaTeX 讲义**

题目以纯文本存在你自己的文件夹里，Obsidian 打开就是同一个库

## 为什么是 Quirex

|  |  |
|---|---|
| **数据是你的** | 一题一文件夹，全是纯文本（`.md` + `.tex`）加普通图片。没有数据库、没有云端，整个文件夹拷走就是完整备份。 |
| **只有一份 LaTeX 真源** | 网页负责渲染它，导出负责把它原样嵌进模板 —— 不会出现「网页上看着对、导出的 PDF 却是另一个样」。 |
| **交付物开箱可编译** | 导出即得到自包含的 `.tex` + `.sty` + `images/`，并自动跑 `xelatex` 产出 PDF。 |
| **完全本地** | `localhost:3000`，不联网、不登录、不上传任何题目。 |

## 快速开始

**Windows：双击 `启动.bat`** —— 它会依次检查 Node → 依赖 → xelatex → 构建产物 → 端口占用，
并且**等端口真正就绪再打开浏览器**。停止服务关掉窗口即可，找不到窗口时用 `停止.bat`。

**macOS / Linux**：需要 **Node.js ≥ 20.9**（Next.js 16 的要求）。

```bash
cd 代码          # npm 命令都在这里跑，package.json 就在这儿
npm install
npm run dev
```

浏览器打开 **http://localhost:3000**

> **导出 PDF 需要本机装有 TeX Live / MiKTeX**（提供 `xelatex`）。没装也能用其它全部功能，
> 导出目录里会留一份 `build.bat`，装好后双击也能编译；装了但不在 PATH，可在「设置 → 路径」里指定完整路径。

> **题库默认是空的**，从「录入」页录第一道题即可。想先看看「满库」是什么样子，在 `代码/` 里跑
> `npx tsx scripts/seed-demo.ts --reset`，会灌进 42 条演示数据（⚠️ 会清空**当前**题库）。

## 五个页面

| 页面 | 路由 | 干什么 |
|---|---|---|
| **题库** | `/` | 关键字搜索、分面筛选（来源 / 知识点 / 年份 / 状态 / 题型）、分页、就地预览、勾选入篮 |
| **录入** | `/add` | 选题型（单选 / 多选 / 填空 / 解答）或整卷，按模板录入、实时校验、重复题拦截 |
| **标签** | `/tags` | 来源 / 知识点 / 自定义 三类标签的改名、停用、恢复、彻底清除 |
| **试题篮** | `/baskets` | 「正在编辑」+ 已保存快照、拖动排序、**导出讲义** |
| **设置** | `/settings` | 学科、模板、导出历史、备份与还原、路径、检索索引、整库备份 |

**浏览状态全部写在地址栏里**（页签、筛选、页码、搜索词）—— 收藏那条链接，就等于收藏这个视图；
从题目详情返回，回的是你来的那一页。

## 从录题到 PDF

```
录入  →  打标签  →  勾进试题篮  →  导出讲义  →  题目.pdf / 答案.pdf
```

导出弹窗里一次定完四项：

| 选项 | 说明 |
|---|---|
| **标题** | 默认当前时间；答案版自动加「（答案）」后缀 |
| **模板** | 自带三套：默认讲义 / 紧凑题单 / 双栏试卷 |
| **分组方式** | 平铺 / 按题型 / 按知识点 / 按来源 |
| **题目信息** | 来源、题号、难度等级、知识点、年份、创新，六项可勾 |

产物**自包含**，拷到任何地方都能编译：

```
导出/期末复习/
├── 题目.pdf / 答案.pdf      题干+留白 / 题干+答案
├── 题目.tex / 答案.tex      生成它们的源码
├── quirex.sty               模板样式（拷走也能编）
├── images/                  题目用到的图片
└── build.bat / build.sh     手动重新编译
```

排版约定：难度只写档位词（基础 / 压轴 / 困难）；创新题带一颗 **★**；多选题一律自带「（多选）」；
整卷不参与导出（它本身就是 PDF）。导出后界面会回报编译是否成功、耗时与警告，
「设置 → 导出历史」可回看并一键打包下载。

## 数据怎么存

**一题一文件夹，文件夹名就是编号。** 编号一旦发出就不回收 —— 题目不能删，录错了改成「停用」，
避免「引用过的题突然没了」。

```
题库/
├── _subjects.json         学科注册表
├── 数学/                  ← 一个学科 = 一套完全独立的题库
│   ├── _meta/             索引、标签表、试题篮、计数器、备份
│   ├── AT0001/            单题：AT0001.md + 题干.tex + 答案.tex（+ 图片）
│   └── AP001/             整卷：AP001.md + 题目.pdf + 答案.pdf
└── 化学/
```

- 单题 `AT0001`、整卷 `AP001`，界面上藏起学科字母，显示为 `T0001` / `P001`。
- 最多 **5** 个学科（字母 A–E），学科名最多 5 个字；各学科的编号、标签表、试题篮、检索索引互相独立。
- 把 `题库/` 当 Obsidian Vault 打开，就能边用网页边翻这些文件 —— **两边改的是同一份东西**。

> 程序按**相对位置**找 `题库` / `模板` / `导出`（就在「代码」的上一层），
> 所以**整个文件夹可以随便挪、随便改名，路径不用重配**。具体路径可以在「设置 → 路径」里改，
> 优先级是 **界面设置（`代码/config.json`） > `.env.local` > 默认值**。换电脑时只需拷走整个 `题库/`。

## LaTeX 怎么写

公式用 `$…$` 或 `$$…$$`（也认 `\[…\]`、`\(…\)`）；选项括号 `\pick`、填空横线 `\fillin`（多选题型会自动补）。
允许的宏是 `\textbf` `\textit` `\emph` `\fig` `\includegraphics`，允许的环境是 `choices` `tabular`。

**不支持** TikZ 绘图、`\newcommand` / `\def` / `\input` / `\usepackage`、svg / webp 图片 ——
这些要么网页端渲染不出来，要么会让题目不再自包含。图片走四个通道：`stem` / `fig` / `ans` / `ansfig`，
在录入页上传即可，文件名与正文引用都由程序生成。

录入时就会校验 LaTeX 与必填项，**通不过就拒绝写入、并把页面滚回顶部说明原因** ——
不会出现「看着保存成功了，其实没进去」。

## 项目结构

```
Quirex/
├── 启动.bat / 停止.bat    日常就用这两个
├── 代码/                  应用本体（Next.js）
│   ├── src/               页面、组件、核心逻辑（题库读写、检索、标签、导出、LaTeX 子集…）
│   └── scripts/           工具与自检（灌演示数据、v0 迁移、各套校验）
├── 模板/                  讲义模板（每个子文件夹一套）
├── 题库/                  题库数据（所有学科都在里面）
└── 导出/                  导出的讲义落在这里
```

## 命令

都在 `代码/` 文件夹里跑：

```bash
npm run dev          # 开发服务器（Turbopack 热更新）
npm run build        # 生产构建
npm run typecheck    # 类型检查
npm run selftest     # 单元自测（315 项，不需要服务器、不碰你的题库）
npm run verify-live  # 接口级端到端校验（需先启动服务）
npm run seed-demo    # 灌 42 条演示数据（--reset 先清空当前题库，慎用）
```

`scripts/` 下另有一批专项校验（模板契约、真实浏览器驱动、迁移结果、源码级验收清单等），
其中浏览器驱动的套件自带一个零依赖的 CDP 客户端，跑之前要先起服务。

> ⚠️ **别把校验套件对着你正在用的题库跑**：多数套件需要库里有题，而且会**往当前题库写测试题**，
> 而题目在设计上不可删，那些测试题会留下。要跑就先灌一份演示数据，或把「题库位置」指到临时目录。

### 给改代码的人

- 别一边跑 `npm run dev` 一边删 `.next`：会弄坏 Turbopack 的缓存数据库（表现为接口全部超时）。要清缓存先停服务。
- 跑浏览器校验套件前先重启一次 dev server，跨大量改动后 Turbopack 会留陈旧模块（表现是「点了没反应」）。
- 文档不是装饰：`verify-v9-readme.ts` 会把《模板规范》里的示例原文抠出来真跑一遍 ——
  改了模板接口就顺手改那份规范，否则它会红。
